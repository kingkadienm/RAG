配套注意事项
1. 双状态机的使用方式（对应 kb_document）：

MQ 消费者拿到消息 → parse_status: 0→1 → Tika 解析+分块成功 → parse_status=2，写 chunk_count
接着 → vector_status: 0→1 → 向量写入 PGVector → vector_status=2，写 vector_count
任一阶段失败 → 对应状态置 3，写 error_msg；重试任务扫描 WHERE parse_status IN (0,3) OR (parse_status=2 AND vector_status IN (0,3))
2. uk_md5_kb 的边界处理：同一文件被拒绝后允许修正重传，应用层插入 REJECTED 记录前先删除同 (file_md5, kb_id) 的旧拒绝记录，否则会撞唯一键。

3. MyBatis-Plus 对应配置：主键 @TableId(type = IdType.AUTO)；deleted 字段加 @TableLogic；created_time/updated_time 用 MetaObjectHandler 自动填充（配 @TableField(fill = FieldFill.INSERT)）。如果你更想用雪花 ID，去掉所有 AUTO_INCREMENT 并改 IdType.ASSIGN_ID 即可，其余不变。

4. vector_store 配合方式：由于你手动建了表（JSONB + GIN 索引），PgVectorStore Bean 里要设 initializeSchema(false)，否则 Spring AI 自动建表会以 json 类型和默认索引覆盖你的优化；维度 1536 与 builder 中的 dimensions(1536) 保持一致。
