# 文件相关代码变更总结

## 一、Mapper XML 更新（适配新 SQL Schema）

### 1. DocumentMapper.xml
- 新增字段映射：`fileMd5`, `vectorStatus`, `vectorCount`, `errorMsg`, `version`
- Base_Column_List 已包含所有新字段

### 2. ChatSessionMapper.xml
- 新增字段映射：`kbId`, `messageCount`
- Base_Column_List 已包含新字段

### 3. ChatMessageMapper.xml
- `references` → `refChunks`（列名 `ref_chunks`）
- 新增 `tokenCount` 字段映射

## 二、Service 层更新

### 1. DocumentService.java
- `create()` 方法签名变更：新增 `fileMd5` 参数
  - 设置 `fileMd5`, `vectorStatus=0`（待向量化）, `vectorCount=0`, `version=1`
- 新增 `updateVectorStatus()` 方法：独立更新向量化状态
- `updateParseStatus()` 增加日志输出

### 2. FileCheckService.java
- `createUploadRecord()` 方法签名变更：新增 `storageType` 参数
  - 存储到 `kb_upload_record.storage_type` 字段

### 3. UploadController.java
- 新增 `storageType` 字段（从配置 `file.storage.type` 注入）
- 流程调整：
  1. 调用 `documentService.create()` 时不传 `filePath`（传 null）
  2. 调用 `fileStorageService.upload()` 获取存储文件名
  3. 回填 `doc.filePath` 和 `record.storedFilename`
- MQ 消息新增字段：`fileMd5`, `storageType`

### 4. DocumentParseConsumer.java（双状态机）
- 引入 `DocumentService` 替代直接调用 `documentMapper`
- **阶段一：解析**（parse_status 状态机）
  - 解析中：`updateParseStatus(docId, 1, 0, null)`
  - 解析成功：`updateParseStatus(docId, 2, chunkCount, null)`
  - 解析失败：`updateParseStatus(docId, 3, 0, errorMsg)`
- **阶段二：向量化**（vector_status 状态机）
  - 向量化中：`updateVectorStatus(docId, 1, 0, null)`
  - 向量化成功：`updateVectorStatus(docId, 2, saved, null)`
  - 向量化失败：`updateVectorStatus(docId, 3, 0, errorMsg)`
- 新增 `localUploadPath` 配置注入
- `readFromLocal()` 方法改为接收相对路径，内部拼 `upload-path`

### 5. ChatService.java
- `ensureSession()` 新增 `kbId` 参数，创建会话时绑定知识库
- `chat()` / `chatStream()` 从请求中提取第一个 `kbId` 传给会话
- `saveMessages()` 更新：
  - 参考文档存储到 `refChunks` 字段（JSON 格式，截取前 100 字符）
  - 新增 `tokenCount` 估算（中文 1.5 token/字符，英文 0.25 token/字符）
  - 更新 `message_count`：`message_count = message_count + 2`
- `buildMessages()` 恢复助手消息入上下文（role=2 → AssistantMessage）

### 6. RetrievalService.java
- 新增 `similarityThreshold` 配置注入（`rag.retrieval.similarity-threshold`）
- 默认值 0.7
